# Stage 4 · 循环执行（内循环引擎的完整操作手册）

SKILL.md ④ 是节奏总纲（压缩后仍在），本文是细则。两者冲突时以 SKILL.md 为准。

## 一轮的完整动作（一轮 = 一条任务）

1. **取任务**：tasks.md 第一条未勾条目；`python3 .loopwork/hooks/progress.py set phase test-writing`
2. **写考题**：把该任务标注的 spec 验收句直译成自动测试。考题原则：
   - 测「用户可见的结果」，不测实现细节；
   - 用假数据替身，不连真实外部服务、不联网；
   - 考题文件统一放 `tests/`；
   - **可证伪自查**：写完自问「改坏实现里哪一行，这条考题会红？」——答不上来 = 考题没咬住行为，重写（永真的考题比没有考题更危险）；
3. **亲眼跑红**：运行考题，确认失败，失败摘要记入 JOURNAL（「红」是证据，证明考卷真的能考住人）。然后**登记红存档**：`python3 .loopwork/hooks/progress.py commit red "存档: T{编号} 红考题"`——你不自己 commit（沙箱里 `.git` 写不动，而且模型自己落的档没人验）。轮末钩子跑在沙箱外，会验「这次只有考题、没有密钥」，验过才落，并顺手推进基线；它挑着收——红档只收 tests/ 和台账，仓库根上其他新文件不自动入档，回执里以「未入档（…）」点名。登记完把本轮的话说完收尾；
4. **看回执**（下一轮开头）：「[代存档] 红存档已落 `<hash>`」= 存住了，可以往下走；「[代存档] 拒绝：…」= 没存住，按理由处理完重新登记，**不许当作已存档继续**；拒绝理由若点名受保护文件（考题/规格/规矩/围栏脚本），处置是撤销（`git checkout -- <文件>` / 删掉新建文件），不是换个档种再登记；
5. **锁围栏**：`progress.py set phase implementing` —— 此刻起围栏锁死 tests/、spec.md、rules.md（测试基建 `tests/conftest.py`、`tests/_infra/**`、`tests/fixtures/**` 例外放行，放行记录在 `.loopwork/logs/allowed.jsonl`）；
6. **写实现**：最小改动让考题变绿；不写投机功能、不顺手重构无关代码；
7. **验证**：`bash .loopwork/hooks/verify.sh`
   - exit 0 = 绿；非 0 = 继续修；
   - 长输出必须 `> .loopwork/logs/round-N.log 2>&1` 然后 `tail -20`，绝不把整版日志倒进对话；
8. **收轮**：绿 → JOURNAL 追加一行 `progress.py journal "T02 ✅ 2 红→绿 | 备注"`（只许追加，改写/删除会被围栏拦下）→ tasks.md 勾掉 → 登记绿存档 `progress.py commit green "存档: T{编号} {任务名}"`。钩子会再跑一遍 verify.sh、核对你手里有没有红存档票（先红后绿），全过才落 commit，并自动推进基线 + 轮数 +1——**所以不要再调 `bump-round`，那会重复计数**。绿档收的是已跟踪改动 + 子目录里的新文件 + 根上台账，仓库根上其他新文件不自动收（回执点名）。下一轮看到「绿存档已落」这一轮才算收掉；
9. **进度播报**（一行）：「✅ 3/12 · 记一笔完成 · 下一条：支出列表」

## 问题本（BLOCKED.md）

触发：要花钱、要装重量级依赖、触碰 rules.md、发现规格矛盾（**含任务引用的规格编号在 spec.md 里不存在**）、超出规格的新想法、以及**方向性二选一**（影响用户可见行为、或以后难改回来的选择）。

**纯实现层的可逆二选一不进问题本**（用哪个内置函数、内部结构怎么组织、先写哪个文件……）：按「最常见、出问题最好修」自己定，JOURNAL 记一行 `T{n} 选 A 弃 B：理由一句话` 即可。问题本留给要用户拍板的事——什么都往里塞，批会死在「只剩受阻」上，用户回来还要替你做本该你做的题。

```markdown
## B03 · 图表库选择
- 问题：饼图需要图表库
- 背景：手写约 200 行；引库 3 行但多一个依赖
- 建议：引 Chart.js（最常见），理由：省 2 小时且更稳
- 状态：待拍板
```

写完**立刻跳过取下一条**，绝不停机干等。被跳过的任务在 tasks.md 标 `〔卡·B03〕`。

## 停批条件（满足任一即停，进 Stage 5）

- 做满一批（state.batch_size，默认 5 条）；
- 撞到 ★ 里程碑；
- 连续 2 条任务受阻；
- round_count 达上限（默认 20，外部计数器管着，不靠你自己数）。

停批汇报格式：本批 N 对 M 点名 + 考题总数与结果 + 问题本新增 + 下一批预告。
**批末状态落盘**：汇报前把 state.json / JOURNAL.md 的未存档改动登记一次记事存档——`progress.py commit note "存档: 批末状态落盘"`，钩子落档并自动推进基线——让记忆真正进历史，会话再断也不丢。

## 失败分级（同一任务）

1 次失败 → 正常修；2 次 → 换思路修；**3 次 → 停止重试，转诊断模式**：读完整日志 → 定位根因（环境？依赖？考题写错？）→ 修根因 → 只再试一次 → 仍败 → 写 BLOCKED.md（含已试方案清单）跳过。

## 挂机批模式（可选，用户同意后开启；Codex 版说明）

- 开：`touch .loopwork/batch.flag` —— Stop 钩子接管外部计数，这批未跑完时自动把你顶回去继续干；
- 自动停（钩子强制）：做满一批（batch_size）→ 去验收；只剩受阻任务 → 去清问题本；达轮数上限 → 安全停机；连续 2 次「一点进展都没有」→ 判定原地打转，自动停批并要求汇报（第 1 次只警告提醒）——**无进展的判据是四条同时成立**：轮数没涨 ∧ HEAD 没动 ∧ tasks.md 没动 ∧ BLOCKED.md 没动；也就是说一条硬任务跨两次顶回不算打转，只要你落了红存档、勾了任务、标了〔卡〕、或往问题本添了一条，都算干出了东西；
- 顶回上限 7 与 CC 版共用一个数（CC 平台硬上限 8 减 1 次余量；Codex 平台本身无上限，这条自停线是唯一刹车）；对照同类工具 repete 默认 25 轮、claude-code-stack 3 轮，取「够跑一批、不撞平台」的中间值；
- 关：批完自动摘 flag；用户随时说「停」→ `rm .loopwork/batch.flag`；
- ⚠️ **首次使用先验证一次**：Stop 钩子需要项目被 Codex 信任才生效——第一批跑 2 条任务盯着看，轮末出现「[挂机档] 批模式进行中…」提示才算接通；没出现就检查信任状态，接通前老老实实手动档；
- 替代挂机方式：教用户原生 `/goal 这批任务全部完成且考题全绿`（Codex 自动多轮推进）——但轮数纪律仍以 `.loopwork` 外部计数为准；
- **起飞前三查**（挂机 = 用户不在场，要拍板的事必须起飞前清干净）：① 相位已复位 `test-writing`；② 本批头 batch_size 条任务没有一条需要现场拍板（有就先问完或先标〔卡〕）；③ BLOCKED.md 里没有会卡死整批的存货；
- 开启前必须量化告知：「这批 N 条任务、预计 X 分钟，期间持续消耗你的额度；我不会中途问你问题——要拍板的事记问题本，批末一起算；中途喊停（`rm .loopwork/batch.flag`）随时生效。」
